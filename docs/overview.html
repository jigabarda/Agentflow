How a run flows

Issue→ Triage→ Implement→ PR→ CI tests→ Review→ Merge→ Deploy

A trigger fires a run; the engine walks the graph node by node, handing each task to the model you assigned. Agents propose code inside an isolated workspace — push, merge and deploy are gated nodes, not agent actions.

Why devs care

  • Clears the boring backlog. Routine issues go from ticket to reviewable PR — you stay the reviewer, not the typist.
  • Right model per task. Cheap Haiku triages, Opus writes & reviews. You pick the model on every node.
  • You keep control. Self-hosted, secrets encrypted, tests run in your CI, destructive steps gated.
  • Design the process once. Encode your team's workflow as a flowchart; it runs the same way every time.
